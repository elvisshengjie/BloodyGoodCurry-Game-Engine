Project Guide
=============

1. Requirements
---------------
Install these first:
- Visual Studio 2022 with Desktop development with C++
- CMake
- PowerShell

Recommended:
```powershell
cmake --version
```

2. Regenerating the Visual Studio 2022 Solution
-----------------------------------------------
From the project root:
```powershell
mkdir build_BloodyGoodCurry_editor
cd build_BloodyGoodCurry_editor
cmake -G "Visual Studio 17 2022" -DSOFASPUDS_ENABLE_EDITOR=ON -DSOFASPUDS_GAME_NAME=BloodyGoodCurry ..
```

To generate for another game project:
```powershell
mkdir build_NewGame_editor
cd build_NewGame_editor
cmake -G "Visual Studio 17 2022" -DSOFASPUDS_ENABLE_EDITOR=ON -DSOFASPUDS_GAME_NAME=NewGame ..
```

Notes:
- `SOFASPUDS_GAME_NAME` selects which game target is built.
- Each game target now resolves its code from `Sandbox/<ProjectName>`.
- Each game target resolves its content from `Games/<ProjectName>`.
- Desktop builds are now separated per game and per mode, so multiple projects can stay configured side by side.

3. Project Structure
--------------------
Each game project is split into code and content.

Code:
- `Sandbox/BloodyGoodCurry` uses the legacy `Sandbox/MyGame` code path.
- New projects use `Sandbox/<ProjectName>`.

Content:
- `Games/<ProjectName>/Assets`
- `Games/<ProjectName>/Data`
- `Games/<ProjectName>/Saves`

Folder purpose:
- `Assets`: source art/audio/resources
- `Data`: authored JSON such as levels, prefabs, and `window.json`
- `Saves`: runtime save data and user-generated state

4. Creating a New Game Project
------------------------------
Inside the editor:
- Open the app in editor mode.
- Use `File -> New Game`.

This now creates:
- `Games/<ProjectName>`
- `Sandbox/<ProjectName>`

Important:
- `New Game` does not auto-load the project.

5. Building and Running
-----------------------
Editor mode:
```powershell
run.bat BloodyGoodCurry
run.bat NewGame
```

Game mode without editor:
```powershell
run_game.bat BloodyGoodCurry
run_game.bat NewGame
```

If you omit the game name, the script uses its default configuration.

Desktop build directories:
- `run.bat BloodyGoodCurry` -> `build_BloodyGoodCurry_editor`
- `run.bat NewGame` -> `build_NewGame_editor`
- `run_game.bat BloodyGoodCurry` -> `build_BloodyGoodCurry_game`
- `run_game.bat NewGame` -> `build_NewGame_game`

If you want to run directly from Visual Studio:
- Set the desired game target as Startup Project.
- Example targets:
  - `BloodyGoodCurry`
  - `NewGame`

Important distinction:
- `New Game` only creates the project folders and starter files.
- To run another coded project, build and launch that project's target.

6. Debug vs Release
-------------------
Debug:
- Best for development
- More logging and symbols
- Use `F9` crash test
- Use `F1` performance panel

Release:
- Optimized build
- Best for performance testing and final runs

7. Editor Shortcuts
-------------------
- `F10`: Toggle editor UI
- `F11`: Toggle fullscreen
- `F1`: Toggle performance window
- `F9`: Crash test
- `T / R / S`: Translate / Rotate / Scale gizmos
- `Delete`: Delete selected object
- `Ctrl+Z`: Undo

8. Spawn Panel Architecture
---------------------------
The spawn panel is now engine-owned.

Engine responsibilities:
- prefab search and selection
- spawn / clear / apply-to-existing
- level save / refresh / load
- generic engine component controls

Game responsibilities:
- register optional spawn-panel extensions
- provide UI and apply logic for game-only components

Current engine-supported component editing in the spawn panel:
- `TransformComponent`
- `RenderComponent`
- `CircleRenderComponent`
- `SpriteComponent`
- `RigidBodyComponent`

BloodyGoodCurry currently registers a game-specific extension for:
- enemy attack
- enemy health
- player attack
- player health
- gate target

New generated projects do not need a custom spawn panel to work.

9. Prefabs for New Projects
----------------------------
Prefab JSON files should go in:
```text
Games/<ProjectName>/Data/Prefabs
```

For a generated project like `NewGame`, the safest test prefabs are:
- engine-only prefabs using built-in components
- prefabs using the template `GlowComponent`

Examples already added:
- `Games/NewGame/Data/Prefabs/TestBox.json`
- `Games/NewGame/Data/Prefabs/TestGlowBox.json`

10. Minimal NewGame Prefab Example
----------------------------------
```json
{
  "GameObject": {
    "Components": {
      "TransformComponent": {
        "x": 0.0,
        "y": 0.0,
        "rot": 0.0
      },
      "RenderComponent": {
        "w": 0.25,
        "h": 0.25,
        "r": 0.2,
        "g": 0.8,
        "b": 0.9,
        "a": 1.0
      }
    }
  }
}
```

11. Generated Game Template
---------------------------
New code projects are copied from:
- `Sandbox/GameTemplate`

The generated project starts with:
- project bootstrap
- `GlowComponent`
- startup level set to `level.json`
- no game-specific spawn extension

12. Web Build and Run
---------------------
Use this for Emscripten/WebGL testing.

Install first:
- Visual Studio 2022
- CMake
- Ninja
- Python 3
- EMSDK

Recommended install commands:
- winget install Kitware.CMake
- winget install Ninja-build.Ninja
- winget install Python.Python.3.12
Quick checks:
```powershell
cmake --version
ninja --version
python --version
em++ --version
```

EMSDK setup example:
```powershell
git clone https://github.com/emscripten-core/emsdk.git $env:USERPROFILE\emsdk
cd $env:USERPROFILE\emsdk
.\emsdk install latest
.\emsdk activate latest
.\emsdk_env.bat
```

Build:
```powershell
build_web_html.bat
build_web_html.bat BloodyGoodCurry release-split reconfigure
build_web_html.bat NewGame release-split reconfigure
```

Default no-argument behavior:
- builds `BloodyGoodCurry`
- uses `release-split`
- forces `reconfigure`
- starts the local Python server automatically

Host:
```powershell
python -m http.server 8000 -d build\web-release-split\Sandbox
```

Open:
```text
http://localhost:8000/BloodyGoodCurry.html?v=1
```

13. Notes
---------
- Do not open the web HTML directly from file explorer.
- Always host with a local server.
- Web builds currently use audio stubs.
- If the editor or build state gets messy, run `clean.bat` and rebuild.
